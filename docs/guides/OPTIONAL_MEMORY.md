# 记忆、知识库、日记与提醒

这些数据保存在本机 `state/`，不会随源码提供。轻量记忆、日记和提醒按 QQ 会话处理，知识库仍为同一仓库实例共用存储。不同模块的隔离范围应分别核对；按会话保存也不等于对本机管理员加密。

先完成 [基础安装](../QUICKSTART.md)，采用 `reserved2`。下面的工具名用于检查 DSH 实际工具列表与调用结果，不需要把管理令牌写入角色卡或发给聊天对象。

## 1. 按会话保存轻量记忆

`socialV2.tools.memory=true` 开放：

| 工具 | 用途 |
| --- | --- |
| `qq_memory_append` | 增加话题、待续想法或成员印象 |
| `qq_memory_query` | 查询当前会话记忆 |
| `qq_memory_remove` | 移除选中的记忆 |
| `qq_memory_clear` | 清空指定范围 |

可保存类别为 `activeTopics`、`pendingThoughts`、`memberImpressions`。工具调用需要当前会话 key 与令牌，桥接检查其对应关系。使用者可让 AI 记住一条无敏感信息，再查询工具结果，确认它确实进入正确会话。

管理员入口是控制台“二代仿真 → 轻量记忆”。从“白名单会话快速选择”选中目标，再加载、编辑或删除。删除或清空会改动已有本机资料，先核对选中的是哪个会话。

已有的成员印象还可能进入自动压缩整理。它是独立设置：

```json
{
  "socialV2": {
    "memory": {
      "consolidateEnabled": true,
      "consolidateMinTraits": 7,
      "consolidateMaxTraits": 5,
      "consolidateCooldownMs": 21600000,
      "consolidateMaxPerRun": 2
    }
  }
}
```

整理使用 DSH 模型并可能压缩表述。只关闭 `tools.memory` 不会同时关闭它；若要停用自动整理，设 `consolidateEnabled=false` 并重启桥接。

## 2. 知识库

知识库位于 `state/knowledge/knowledge.jsonl`，适合保存可重复使用的事实、来源说明或操作经验。

| 工具 | 用法 |
| --- | --- |
| `qq_knowledge_add` | 保存标题、正文、标签；可设置有效天数 |
| `qq_knowledge_search` | 按关键词搜索 |
| `qq_knowledge_recent` | 查看最近条目 |
| `qq_knowledge_delete` | 按查询返回的真实 id 删除 |
| `qq_knowledge_prune` | 清理符合条件的旧条目 |
| `qq_knowledge_consolidate` | 只读列出可能重复、过期或陈旧的条目供审阅 |

初次使用可以让 AI 保存一条无私人信息的资料摘要，然后按标题搜索。检查返回是否是刚才的条目；相同规范化标题会更新旧条目，不一定新增一条。

标题最多 80 字、正文最多 2000 字、标签最多 8 个；库容量最多 2000 条，每日新增限额 40 条。`expiresInDays` 的范围是 1–365。`consolidate` 本身不合并或删除；真正修改需分别调用新增、删除或清理工具。

目前没有独立知识库页面或 `knowledge.enabled` 开关，也不会在每轮自动把整库注入上下文。读取依靠工具查询，`tools.memory=false` 不会关闭知识库。

## 3. 日记

`qq_write_diary` 保存正文及可选标题、心情、标签；`qq_read_diary` 读取最近日期或指定日期。两个工具都必须提供当前会话的 `token`，桥接通过令牌反查会话，不根据模型自报的目标选择日记本。缺少或无效令牌、会话不再被允许时拒绝操作。

每个私聊或群聊分别存入 `state/diary/sessions/<scope>/`，含索引和按日保存的 Markdown。`scope` 由会话 key 转换而来；目录名及内容仍可能识别聊天对象，不应上传。

需要时可让 AI 写一条确实发生的、无敏感内容的记录，再在同一会话用读取工具核对。每个会话一天最多 20 条，单条正文最多 4000 字；读最近 `n` 天时范围为 1–7，默认 2。当前没有日记专用控制台页面。

近期日记是否自动进入唤醒提示由以下字段控制：

```json
{
  "socialV2": {
    "context": {
      "diaryInPrompt": false
    }
  }
}
```

设为 `false` 只停止自动注入，不关闭 `qq_read_diary` / `qq_write_diary`。启用注入时只读取当前会话的日记，并按会话缓存；不会把另一会话日记拼入本轮提示。知识库等其他存储的范围不随之改变。

从旧版升级时，旧 `state/diary/` 根目录文件不会自动分配、归档或迁入各会话。底层日记库仍保留不带 key 的兼容入口，但聊天运行时始终带会话身份。先保留旧文件；确需迁移时，只把能核实归属的条目交由管理员单独整理，不能把整本旧日记复制给每个聊天对象。升级说明见 [会话功能教程](SESSION_FEATURES.md)。

## 4. 提醒

`socialV2.tools.reminder=true` 开放 `qq_set_reminder`、`qq_list_reminders`、`qq_cancel_reminder`。该键可以显式加入配置；省略时源码默认启用。

使用顺序：

1. 确认目标会话已被允许，时间和提醒内容正确，再请求创建。
2. 查看工具返回的实际时间与 id；用 `qq_list_reminders` 回读。
3. 取消时使用列表中真实 id，并再次检查列表。

时间参数 `dueAt` 使用 Unix 毫秒；文本最多 200 字，未来时间最多 60 天。每会话待触发上限 20 条，全局 200 条，存储为 `state/reminders.json`。

桥接约每 30 秒扫描。到点后会唤醒对应 AI 会话，提示到期提醒；它不是独立系统闹钟，也不保证按原文在精确秒数发送。需要桥接和 DSH 就绪、二代模式运行且未暂停。已不被允许的会话会跳过；持续繁忙也可能导致放弃。

**关闭提醒工具不会取消已建立的提醒。** 要停止已有提醒，先列出并逐项取消；不要把删除整个 `state/` 当成取消某条提醒的方法。实际提醒可能促成 QQ 发送，因此离线安装检查不创建提醒。

## 5. 黑话与风格不是同一份记忆

黑话词库、成员印象、风格例句、日记和知识库的保存及注入机制各不相同。关闭某一个开关不会自动清空其他存储；具体自动学习设置见 [学习和自动运行](OPTIONAL_AUTOMATION.md)。

`state/`、含真实内容的工具日志和截屏不应上传。备份要保留在自己的受控位置，分享问题时只提供脱敏最小样例。返回 [可选功能索引](../OPTIONAL_FEATURES.md)。
