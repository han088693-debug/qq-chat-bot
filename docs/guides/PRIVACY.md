# 隐私与发布检查

本仓库提供源代码和通用模板，不提供使用者的运行环境。无论仓库当前是私有还是公开，真实配置、聊天记录和个人素材都应留在本机。

## 不提交的内容

| 类型 | 例子 |
| --- | --- |
| 账号与访问范围 | 真实 QQ 号、群号、联系人名单、好友或群聊关系 |
| 凭据 | OneBot access token、控制台/会话令牌、模型 API Key、Cookie、DSH 凭据文件 |
| 运行记录 | 会话映射、聊天日志、工具调用记录、用量明细、诊断输出 |
| 个人内容 | 私密角色卡、昵称与关系设定、长期记忆、知识条目、日记、提醒 |
| 媒体与截图 | 聊天截图、头像、私人图片、音频、语音转写结果 |
| 机器信息 | 真实用户名、个人目录、设备资料、包含私人信息的启动参数 |
| 外部软件数据 | SnowLuma 和 QQ 登录数据、DSH 会话和本机凭据、手机配套服务状态 |
| 本地审阅材料 | 私人工作文档、未脱敏复现、备份、含真实标识的扫描规则 |

`config.example.json` 只保留空值和通用选项；真实值填写到被忽略的 `config.json`。公开角色示例应重新编写，不能仅删除角色卡中的账号号码就认定完成脱敏。

可选模块同样只发布 `optional/config.example.json`。真实 `optional/config.json`、设备序列号、SideTap 配对与签名资料、B 站登录凭据及二维码留在本机。iPhone 的可选截图写入 `state/optional/iphone-shots/`，不要把它当作可公开的普通输出目录。

QQ 空间巡逻的允许/屏蔽名单只填在本机配置中；`state/optional/qzone-patrol/` 保存候选的账号和动态标识、动作哈希、时间、配额与运行状态，也属于私人数据。动作哈希不等于匿名资料。巡逻自身不把动态正文或评论正文写入状态文件，但 MCP 的扫描结果会返回动态摘要；DSH、模型服务和网关可能另有记录，分享诊断材料前仍需检查。

## 运行时数据可能去哪里

- 允许接入的 QQ 消息会经 SnowLuma 进入桥接；消息、媒体和组装后的上下文可能发送给 DSH 配置的模型服务商。
- 启用搜索时，查询会交给配置的搜索后端；`auto` 模式可能使用回退服务。热榜也会向对应外部站点发请求。
- 记忆、日记、词库、消息活动和用量会保存在本机状态目录；DSH 另有自己的会话记录。
- 本地语音转写使用外部程序及本地模型，但转写结果之后仍可能随聊天上下文发送给模型服务。
- 可选手机、QQ 空间和 B 站 MCP 的读取结果可能进入 DSH 模型上下文；只读不表示数据不离开本机。独立服务有自己的权限，不能从桥接的白名单推断它们的全部行为。
- 巡逻的 `dryRun=true` 只阻止点赞和评论提交，不阻止读取网关。定时进程的输出只提供运行概况；通过 MCP 扫描取得的动态仍可进入 DSH 上下文。

把对象加入白名单、开启学习或接入外部工具前，应确认哪些数据会进入该路径。公开仓库没有携带私人数据，并不表示程序运行后不会生成私人数据。

## 辅助扫描

在仓库根目录执行：

```powershell
npm run privacy-scan
```

也可以只检查已跟踪文件：

```powershell
node scripts/privacy-scan.mjs --tracked-only
```

扫描器离线读取工作树中的候选文件，检查部分路径、账号数字、疑似凭据和禁止提交的文件名。Git 可用时，默认候选集为已跟踪文件加未被忽略的未跟踪文件；它不是 Git 暂存区内容或完整提交历史的审计器。

需要匹配自己的标识时，在本机创建规则副本：

```powershell
Copy-Item -LiteralPath .\scripts\privacy-rules.example.json -Destination .\scripts\privacy-rules.json
```

仅在本机副本里填写真实标识，保留该文件的忽略规则。修改正则时注意转义，并检查命中是否覆盖预期形式。

### 扫描盲区

扫描通过只表示现有规则未发现问题：

- `allowPaths` 按文件路径跳过内容扫描。目前包括部分源码、配置模板、锁文件、测试及本页等文件；这些内容仍需人工或独立检查。
- 纯中文称呼、私人关系、故事化角色描述、截图中的文字等，未必匹配账号或凭据规则。
- 忽略目录、二进制内容、文件大小限制，以及 Git 不可用时的目录遍历，都可能使检查不完整。
- 默认数字和高熵规则有误报与漏报，不能当成完整的秘密检测工具。
- 扫描工作树不等于检查旧提交、Release 附件、Issue、PR 讨论、日志附件或其他远端副本。

不要为了得到“通过”而把新增可疑文件整项加入 `allowPaths`。先确认具体命中是示例还是私人数据，再处理内容或完善规则。

## 提交前查看最终内容

在本机检查待提交文件和实际差异：

```powershell
git status --short
git diff --cached --stat
git diff --cached
```

查看新增文档、配置模板、代码注释、测试夹具以及图片等文件，确认其中没有个人信息。不要只看文件名，也不要把整份检查输出直接贴到公开讨论中。

`.gitignore` 只帮助排除尚未跟踪的文件，不会自动移除已经跟踪的秘密，更不会清理历史提交。新仓库发布时，可以只导出审查过的源代码快照，不复制旧运行目录或旧 `.git` 历史。

如果凭据已经提交或对外暴露，优先撤销或轮换它，再处理仓库记录；删掉当前文件不能让已复制的内容失效。对于已经公开的私人消息或素材，应根据实际暴露位置处理，不声称删一次文件就完成所有副本清理。

## 分享问题报告

报告软件版本、发生的步骤、错误类型和最小复现即可。用通用占位符替换聊天对象和路径，移除令牌、带登录凭据的链接、模型密钥以及消息正文中的私人信息。若必须提供完整日志或截图，先在本机审阅，使用适合该内容的私密渠道。
